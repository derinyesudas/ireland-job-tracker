Turn the board lock off until the vault passphrase is recovered

The passphrase does not open data/keys.json - neither the owner nor the
recovery holder. GitHub Actions can still encrypt, because it holds
TRACKER_KEY as a repo secret, but a secret cannot be read back out. So an
encrypted board would be readable by nobody, including its owner.

The workflow's lock steps are commented out rather than deleted.

site/app.js now decides for itself: it asks for data/jobs.json.enc, and only
shows the unlock screen if that file is actually published. No .enc, no
password - it loads the plaintext board. So re-enabling the lock later needs
nothing on the page side, just the two workflow steps uncommented.

Everything else is untouched. The eligibility filtering is independent of the
lock and keeps working.
